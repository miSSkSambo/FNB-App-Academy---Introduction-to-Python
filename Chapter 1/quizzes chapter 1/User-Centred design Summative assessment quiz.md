# Design Thinking and App Development — Quiz Questions and Answers

## 📘 Overview

This quiz covers the essential principles of design thinking and app development, including user-centred design, problem statements, personas, value propositions, prototyping, wireframes, inclusive design, and project scope management.

## 🎯 Learning Objectives

- Understand the five stages of design thinking.
- Identify real user needs and problems.
- Explain personas and value propositions.
- Understand the purpose of prototypes and wireframes.
- Apply inclusive design principles.
- Prioritise features using the MoSCoW method.
- Plan realistic app development projects.

---

## 📝 Quiz Questions and Answers

### Question 1: What is the primary goal of user-centred design?

**Answer: B — To base every design decision on the real needs of the person who will use the app.**

User-centred design focuses on users' needs, experiences, and challenges.

### Question 2: Why do designers create personas instead of designing for everyone?

**Answer: D — Because designing for an imagined "everyone" usually produces a vague app that serves no one well.**

Personas help designers focus on specific user groups and their needs.

### Question 3: Which of these is NOT one of the five stages of design thinking?

**Answer: B — Deploy.**

The five commonly used stages are Empathise, Define, Ideate, Prototype, and Test.

### Question 4: What risk arises when a learner skips empathy research and codes a feature they personally think is cool?

**Answer: B — The feature may not solve a real problem for the actual target user.**

Research helps ensure that the app addresses genuine user needs rather than personal assumptions.

### Question 5: What is a value proposition?

**Answer: B — The specific benefit a product delivers to its users.**

A value proposition explains why users would benefit from using a product.

### Question 6: What is a wireframe?

**Answer: D — A simple, rough sketch of a single screen's layout using boxes and labels.**

Wireframes communicate the structure and placement of interface elements before detailed visual design.

### Question 7: What should a good problem statement include?

**Answer: A — A specific user, a specific pain point, and why it matters.**

A clear problem statement identifies who experiences the problem and why it needs to be addressed.

### Question 8: What should most influence whether offline support is a Must-have feature?

**Answer: D — Whether the target persona commonly experiences unreliable or costly data access.**

Features should be prioritised according to the real circumstances and needs of target users.

### Question 9: What is a prototype in design thinking?

**Answer: D — A low-cost, low-effort version of an idea used to test it cheaply.**

Prototypes allow designers to gather feedback and improve ideas before investing in full development.

### Question 10: A screen sketch showing a login title, two text fields, and one button, without colours or final wording, is an example of what?

**Answer: A — A wireframe.**

A wireframe focuses on screen structure rather than final styling.

### Question 11: What is wrong with the statement "spaza shop owners need a stock-tracking app"?

**Answer: C — It already names a solution, which forecloses other ideas before they are explored.**

A problem statement should focus on the user's problem before deciding which solution to build.

### Question 12: What is a persona in app design?

**Answer: A — A short, semi-fictional profile representing a real segment of your target users.**

Personas summarise characteristics, goals, behaviours, and challenges of a target user group.

### Question 13: Why do designers create personas instead of designing for everyone?

**Answer: D — Because designing for an imagined "everyone" usually produces a vague app that serves no one well.**

Personas help make design decisions more focused and relevant.

### Question 14: What is the purpose of realistic Must-have feature scoping for a capstone project?

**Answer: B — It is the single biggest predictor of finishing a working project on time.**

A realistic scope helps developers concentrate on essential features and complete a functional product within the available time.

### Question 15: What does a feature marked "Won't-have" in MoSCoW mean?

**Answer: D — It is explicitly out of scope for this version of the project.**

MoSCoW categorises requirements as Must-have, Should-have, Could-have, and Won't-have.

### Question 16: What is accessible design primarily concerned with?

**Answer: B — Making an app usable for people with visual, hearing, motor, or cognitive differences.**

Accessible design removes barriers that may prevent people with different abilities from using an application.

### Question 17: How should core app features relate to Phase 2 business concepts?

**Answer: D — Every core feature should trace back to the value proposition or target market.**

Features should support the app's intended users and the benefit the product promises to deliver.

### Question 18: Why is scoping a project around a realistic Must-have list important for a capstone?

**Answer: B — It is the single biggest predictor of finishing a working project on time.**

Prioritising essential features reduces the risk of an unfinished or rushed project.

### Question 19: What is the best reason to test a prototype with real users before building the final app?

**Answer: A — To avoid spending significant development time building the wrong solution.**

User testing reveals problems and provides feedback while changes are still relatively inexpensive.

### Question 20: Why does design thinking recommend not judging ideas during the Ideate stage?

**Answer: A — To maximise the number and variety of ideas generated before narrowing down.**

Generating a wide range of ideas encourages creativity before evaluating and selecting the most promising solutions.

---

## ✅ Key Takeaways

- Design around real users and their needs.
- Define the problem before choosing a solution.
- Use personas to understand specific target audiences.
- Make sure features support the value proposition.
- Use prototypes to test ideas before full development.
- Use wireframes to plan screen layouts.
- Apply accessibility and inclusive design principles.
- Prioritise essential features using MoSCoW.
- Keep project scope realistic to meet deadlines.
- Generate a variety of ideas before evaluating them.

## 📚 Conclusion

Design thinking supports the development of useful, user-centred applications through research, problem definition, idea generation, prototyping, and testing. Combining these methods with realistic project scoping helps developers build accessible solutions that address genuine user needs.
